# Архитектура: этап 1

## Что есть на этапе 1

- Лента постов с вкладками: Все · Семинары · Статьи · Тренажёры · События.
- Страница поста: текст (Markdown), презентация (слайды из PDF), встроенный тренажёр, файлы.
- Тренажёр на весь экран.
- Страница тега.
- Статистика без регистрации: просмотры, завершения, результаты тренажёров с первой попыткой и именем по желанию.
- Посты создаются в панели Supabase (редактора пока нет).

## Из чего состоит

```
Репозиторий teacher-hub
├── src/                  → проект Vercel №1: сайт (Next.js)
├── play/                 → проект Vercel №2: тренажёры (статичные HTML, отдельный домен)
├── supabase/migrations   → схема базы (схема `hub` в вашем Supabase)
└── docs/                 → архитектура и протокол тренажёров
```

```
Браузер ──► Сайт (Next.js, Vercel) ──► Supabase: схема hub (Postgres + RLS)
   │                 │                  └─ Storage: бакет hub-public (обложки, PDF, файлы)
   │                 └─ <iframe> ──► play-домен (Vercel): тренажёры
   │                                     │
   └──────── postMessage (протокол v1) ◄─┘  тренажёр сообщает результат,
                                             сайт проверяет и пишет в базу
```

## Страницы

| Адрес | Файл |
|---|---|
| `/`, `/?type=seminar` | `src/app/page.tsx` |
| `/p/[slug]` | `src/app/p/[slug]/page.tsx` |
| `/p/[slug]/play/[asset]` | `src/app/p/[slug]/play/[asset]/page.tsx` |
| `/tag/[tag]` | `src/app/tag/[tag]/page.tsx` |

Страницы рендерятся на сервере и обновляются раз в минуту (`revalidate = 60`).

## Текст поста

`posts.content_md` — Markdown со вставками на отдельной строке:

```
::presentation[slides]
::trainer[ielts]
::file[plan]
```

В скобках `slug` вложения из `assets`. Вложения, которые не вставлены в текст, показываются после текста: сначала презентация и тренажёр, внизу файлы.
`posts.body jsonb` зарезервировано под визуальный редактор этапа 2. Markdown туда конвертируется.

Сырой HTML в тексте не выполняется (react-markdown), поэтому вставить скрипт в пост нельзя.

## База (схема `hub`)

| Таблица | Назначение |
|---|---|
| `schools` | школы (на будущее: сеть) |
| `profiles` | авторы, `id` = пользователь Supabase Auth |
| `posts` | посты: тип, статус, видимость, текст |
| `tags`, `post_tags` | теги |
| `assets` | вложения: PDF, pptx, файлы, тренажёры (по `url`) |
| `events` | просмотры и завершения (anon_id) |
| `results` | результаты тренажёров (anon_id, lesson, score, first_try, имя) |

## Доступ (RLS)

| Кто | Что может |
|---|---|
| Любой посетитель (ключ anon) | читать опубликованные посты (`public` и `link`), теги, вложения, профили; добавлять события и результаты только к опубликованным постам; вызывать `post_stats()` (только итоговые цифры) |
| Вы в панели Supabase | всё (панель работает в обход RLS) |

Результаты и события посетители **не могут читать**: политик на чтение у этих таблиц нет.

Видимость `link`: пост открывается по прямой ссылке, но не показывается в ленте и на страницах тегов. Это не секретность: через API такой пост можно найти, поэтому закрытое по ссылке не публикуйте.

## Безопасность, сделанная на этапе 1

- RLS на всех таблицах. Секретный ключ в проекте не используется вообще.
- Тренажёры на отдельном домене в `sandbox`-iframe. Сообщения проверяются по `origin` и `source`.
- Content-Security-Policy: iframe разрешены только с play-домена, запросы только к вашему Supabase.
- Ограничения в базе: длины строк, `score ≤ max_score`, типы и статусы через `check`.

## Этап 2 (дальше)

- Вход (почта или Microsoft), профиль автора.
- `/write`: визуальный редактор TipTap, загрузка файлов через форму. Политики RLS «автор правит свои посты».
- `/dashboard`: мои посты и статистика по заданиям.
- Загрузка тренажёров через сайт: хранилище плюс отдача с play-домена.

## Этап 3

- Ссылки с кодом для учителей (`assignments`, `participants`).
- Комментарии, реакции «Полезно» и «Применила на уроке», подписки, уведомления.
- Другие авторы, песочница, модерация.
